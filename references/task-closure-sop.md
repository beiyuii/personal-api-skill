# Task Closure SOP

Use this SOP near the end of a task when the result should become durable.

Short rule:

> Result to Obsidian. Learning to Memory candidate. Method to SOP. State to project page.

## When To Run

| Mode | Closure Behavior |
|---|---|
| `light` | Skip unless the user asks for sedimentation. |
| `standard` | Do a brief closure check and update obvious local files when already in scope. |
| `strict` | Run the full checklist and report what was written or why it was only proposed. |

## Closure Checklist

1. Project status
   - Update `00.context/projects/project-overview.md` or the relevant project page when the task changes project state.
2. Obsidian knowledge
   - Put durable notes under `30.knowledge/40.notes/`.
   - Put reusable methods under `30.knowledge/50.frameworks/operation/`.
   - Put publishable outputs under `30.knowledge/70.outputs/`.
3. Memory candidate
   - If a durable cross-project lesson emerged, output it as `Memory candidate`.
   - Do not claim memory was saved unless a real memory write occurred.
4. SOP update
   - If the workflow changed, update or propose an SOP entry.
5. Next action
   - State the next practical step or say none is needed.

## Output Format

For `standard` mode:

```text
Closure:
- Project status: updated / not needed
- Knowledge: updated / not needed
- Memory candidate: yes / no
- SOP: updated / not needed
```

For `strict` mode, include file paths and verification evidence.
